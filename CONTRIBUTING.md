# Contributing to AHT

Thank you for taking the time to improve AHT. Suggestions, bug reports, and focused improvements are welcome.

## Before making a change

- Check the existing issues to avoid duplicating reported work.
- For larger changes, open an issue first to discuss the proposed approach.
- Keep changes focused and avoid unrelated refactoring.

## Development workflow

1. Fork the repository or create a dedicated branch from `main`.
2. Use a descriptive branch name, such as `fix/mobile-navigation` or `docs/readme-update`.
3. Install dependencies using the package manager and lockfile in the repository.
4. Make the change and run the relevant checks available in `package.json`.
5. Commit with a clear message describing the change.
6. Open a pull request against `main` and explain the motivation, implementation, and testing performed.

## Pull request checklist

- [ ] The change has a clear and limited scope.
- [ ] Existing behavior is preserved unless the change intentionally updates it.
- [ ] Responsive behavior has been considered where the UI is affected.
- [ ] Relevant checks have been run, or any unrun checks are clearly noted.
- [ ] Screenshots are included for meaningful visual changes.
- [ ] Documentation is updated when needed.

Please be respectful and constructive in discussions. Thank you for helping make AHT better.
